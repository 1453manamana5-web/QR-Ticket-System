# 無料Sparkプランでの運用

2026-10-28: 本番はFirebase Authentication（匿名認証）とCloud Firestore、GitHub Pagesを使用する。Cloud Functions・Cloud Build・Artifact Registryの本番利用を前提としない。Blazeへの変更や新たなAPIの有効化は不要。

## 維持する機能

受付の端末保存と再接続時の同期、管理端末による受付端末の申請・承認、イベント作成・公開・終了・個別削除、チケット発行・デザイン・印刷、分析、バックアップは既存のFirestore SDKとSecurity Rulesで実行する。今回ルールの権限は変更しない。

## 変更点

- 実際にFunctionsを呼んでいたのは管理画面の全データ初期化だけだった。このボタンとCallableクライアントを削除した。全端末・管理者・孤立したサブコレクションまでの完全削除をブラウザで安全に再現できないため、同名の不完全な代替処理は作らない。
- 設定画面の「設定を初期状態に戻す」は維持。この端末のアプリ設定だけを戻し、イベント・チケット・受付履歴・承認情報を保持する。イベント単位の削除はイベント管理から行う。
- Functions本番公開用Actionsを削除し、既定のfirebase.jsonからfunctionsを除去。Functionsソースは参考・管理者移行ツールとして保持する。エミュレータでの既存サーバーコードのテストは課金サービスへ接続しない。

## 運用条件と制限

Sparkの無料枠には読み書き・保存量の上限があり、超過時は処理が制限される。今回の変更で本番プランやIAMは変更していない。既に承認済みの管理端末を保持する。最初の管理者の作成・紛失時の復旧は信頼できる管理環境から行い、一般端末の自己昇格は許可しない。

完全オフラインの別iPad間で状態を即時共有する機能はない。iPad実機の音声・カメラ・印刷は別途確認する。

本番データの削除・初期化・認証設定の変更は、今回の検証では実行しない。
