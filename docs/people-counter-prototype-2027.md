# 2027年文化祭 自動人数計測 試作版

## URL
https://1453manamana5-web.github.io/QR-Ticket-System/people-counter/

このページは `reception-app/public/people-counter/` に独立して設置されています。
既存の受付・管理画面、Firebaseのデータ、来場分析には一切書き込みません。

## ねらい
普通の引き戸を基本1人ずつ通る来場者を、iPadの背面カメラだけで自動計測できるか評価する。
来場者へチケット・スタンプ・番号などを渡さない。
再入場は基本的に発生しない前提。ただし入場しないスタッフは誤計測対象になり得ます。

## 使い方
1. iPadのSafariで上記URLを**オンライン**で開く。
2. iPadの背面カメラを、高さ約1.3〜1.5mで引き戸から少し離れた三脚か机上に固定。通路を塞がないこと。
3. 「計測を開始」をタップ。Safariのカメラ権限を許可する。
4. 映像内で来場者が左→右に動くなら「左→右」、手前→奥に動くなら画面内の移動方向を見て「上→下」「下→上」を選ぶ。
5. 青いA線が入口手前、緑のB線が入口後になるよう位置スライダーを調節する。
6. 1人ずつ、速く連続、立ち止まり、逆走、スタッフ通過の順で手動数えと比較する。
7. 明らかな誤差は±1で訂正。「CSV出力」で時刻付き試験記録を取得する。

## 実装
- Safariの `getUserMedia`、MediaPipe Object Detector（EfficientDet-Lite0）、BodyPix MobileNetV1 0.75を使用。
- personの検出候補に対して、同じフレームの肩〜腰の胴体領域を別モデルで確認。頭・顔・腕・手・脚は確認根拠に使わない。胴体領域の中心を短時間追跡し、腕の動きによる人物枠の中心のずれを避ける。
- 同一追跡がA→Bを越えた時だけ+1。逆向き・Aのみの通過は加算しない。
- カメラ映像・顔・永続的な人物IDは記録しない。時刻・増減数・操作種別だけIndexedDBへ保存。
- 「新しい試験」は別セッションIDを発行する。前回の端末内記録は自動削除しない。
- Firebase同期・スタッフ判別・混雑時の重なり補正は**未実装**。
- モデル・WASM・SDKは外部ネットワークから読み込む。現版では**オフラインから新規起動する計測は保証しない**。ネット切断後も、既に起動した画面での記録はIndexedDBへ保存を試みる。
- iPad実機での性能・モデル読込・カメラ精度は未検証。実人数の正確性や99%精度を保証しない。

## 技術上の限界
人物検出に失敗した場合や人が重なった場合はカウント漏れになる。誤検出・再追跡で過大カウントもあり得る。
来場者とスタッフを判別しないのでスタッフが通った分は訂正する必要がある。
Safariが非表示・スリープになると計測は止まるため、常時前面表示と給電が必要。
校内Wi-Fiが jsdelivr.net / storage.googleapis.com を遮断した場合、モデル読込が失敗する。
本番運用前に学校側のカメラ使用許可・撮影案内を用意する。入口で転倒・避難経路の支障が起きないようにする。

## 検証チェック
- 100回の単独通過、100人連続通過、途中で引き返す10回、逆方向10回
- 照明や来場者の服装の違い、ドア位置、カメラの高さと角度
- 30分以上の連続計測、Wi-Fi切断、Safari再読込後に記録が残るか
- 手動実測値に対して誤差率と過大計測・過小計測を別々に記録

現行バージョンは試作用。正式な会場来場者数として扱わない。

## Ver.0.2 真横モード（2026-11-15）
- 「カメラの設置」に「真横・横向きの通過（試験）」を追加。初期設定は真横モード。斜め上用の標準モードも選択可能。
- 真横モードは検出スコア0.30以上を候補とし、3フレーム以上・平均0.34以上の追跡で確定。標準は0.45以上・2フレーム以上。どちらもA→Bの移動が必要。
- 真横モードの解析間隔は最短100ms（目標最大10回/秒、機種によって低下）。同じ映像フレームの重複解析を除外。
- 下半身が画面端で切れた際の影響を減らすため、真横モードでは検出枠の上寄りを追跡。映像に黄色い追跡点・人物検出スコア・追跡確認数を表示。
- 速い横移動・最大1秒までの短い見失いを考慮した追跡。別人との取り違えを完全には防げない。
- カメラは1280×960を希望（端末が対応する解像度で起動）。頭から腰がなるべく画面内に入る距離に固定し、画面の左→右／右→左に動くよう設置する。追跡点が両ラインの手前から奥まで見える位置が必要。
- 検出モデル自体の再学習はしていない。横向き・上半身だけの実映像で精度が改善したかは未検証。画面に入らない人、重なった人、暗い場所では検出漏れが残る。
- `npm run test:people-counter` で4方向、速い通過、短い見失い、連続来場、逆走、引き返し、弱い誤検出、枠の切れを検証する。これらは追跡ロジックの試験で、カメラ認識精度を示さない。

## Ver.0.3 腕だけの誤計測対策（2026-11-15）
- 利用者から「腕で試しても反応する」と報告があったため、人物検出のスコアだけでは通さず、別のPose Landmarker Liteモデルによる頭・肩・腰の確認を追加。
- 両モデルには同じ一時キャンバスの画像を入力する。各ランドマークのvisibility 0.6以上、presenceがある場合は0.6以上、画面内・同じ検出枠内にあること、頭→肩→腰の上下関係と胴体の長さを検査する。
- 横向きでも左右両方は要求せず、見えている片側の肩・腰と頭で確認する。脚や足は要求しない。頭や腰が画面外、強い遮蔽、深い前かがみ、遠すぎる人は対象外になり得る。
- 1つの骨格を複数の検出枠に使い回さない。前フレームの確認結果を腕だけのフレームに流用しない。
- 追跡点を肩→腰の35%の点に固定。胴体が動かず腕を振って人物枠だけが横に動いても、通過として加算しない。
- 黄色の枠・線は頭と胴体を確認した計測候補。灰色は未確認候補で、追跡・人数加算に渡さない。設定に関わらず両モードで確認を行う。
- 確認モデルが読めない場合は計測開始を中止し、人物検出だけでの運転には切り替えない。GPUが使えない場合は各モデルをCPUで試行する。
- モデルが1つ増えるため初回読込と推論の負荷が増える。iPadでの検出速度・連続動作は実機で確認が必要。
- 画像とランドマークはフレーム処理のメモリ上だけで使用し、保存・外部送信しない。
- 回帰テスト34件で、人物と誤認された腕の排除、手首・肘だけ、見えない腰、画面外の腰、横向きの人物、腕振り、二重枠、モデル読込失敗を検証。実際の利用者の腕の映像は未取得であり、現場での誤認排除率は未検証。

- 実モデル（MediaPipe 0.10.35・CPU、Web版と同じ2つのモデルファイル）でも公式サンプルの腕部分を人物と誤認するケースを再現。骨格にも1フレーム誤認が出たため、検出枠の高さが幅の0.65倍未満の極端に横長の候補を除外する条件を追加。
- 人物全体・頭から腰・横向きの腕・縦向きの腕・無人・人物の直後の腕の7場面×3フレームで、人物画像は受理し、腕と無人は除外できることを同じJavaScriptの判定関数で検証。1枚から作った限定的な画像検証であり、多様な来場者・iPadの実カメラ・実時間性能を保証するものではない。
- Cloud ChromeではWebGLコンテキストを作れずWeb版の実推論は検証不可。UI確認とCPU版での画像検証は分けて扱う。

## Ver.0.4 肩〜腰を主判定に変更（2026-11-15）
- 頭を必須にせず、肩〜腰の胴体が映れば確認できる方式に変更。頭・顔・足を画面に入れる必要はない。ただし胴体の大部分が隠れたり画面外になった場合は見逃し得る。
- Ver.0.3の骨格モデルは、頭を除いた画像で骨格自体を検出できなかった。そのため条件削除だけで済ませず、確認モデルをBodyPix MobileNetV1（0.75、stride 16、quantBytes 2）へ置換。
- BodyPixのtorso_front/torso_back（部位ID 12/13）だけを根拠にする。頭・腕・手・脚の部位ラベルは計測根拠から除外。大きさ・縦横比・密度を満たす連続した胴体領域と、対応する人物枠の重なりを確認する。極端に横長の人物枠の除外も維持。
- 重複する人物枠に同じ胴体領域を二重に割り当てない。黄色い追跡点は胴体領域の重心。前フレームの胴体を現在の腕だけの画像へ使い回さない。
- TFJS 4.22.0、BodyPix 2.2.1を固定。WASMを優先し、初期化できない場合はWebGLで実行。標準デコーダの整数行列積はWASM非対応のため、公開baseModelの出力をargmaxで部位IDへ変換する専用デコーダを使用。頭や骨格の位置は判定条件に使わない。
- 解析用スナップショットは幅最大640px、胴体モデルは幅最大320px相当。入力の縮小に合わせて映像上の枠の座標を変換する。
- 非同期解析は1フレームずつ処理し、同時実行しない。停止後・設定変更後・画面非表示後に届く古い結果は破棄。再開時は以前の解析が終わるまで入力を上書きしない。
- 回帰テスト40件で、頭なしの胴体、背中、横向きの細い胴体、腕・手・顔・脚の排除、微小領域、二重計測、停止中や設定変更中の遅延結果を検証。
- 公式人物サンプルの人物全体／頭を除いた肩〜腰／横向きの腕だけ／縦向きの腕だけ／無人を比較。BodyPixの公式CPUデコーダと専用WASMデコーダでマスクの一致を確認し、人物枠と組み合わせた18フレームで期待する受理・除外を確認。限られた画像の検証であり、iPad実機や会場での精度・速度は未検証。
- Chromeブラウザ内の実WASMモデルでも5場面すべての受理・除外が期待どおりであることを確認。人物検出部分との結合は上記の同一画像に対する検出結果で検証し、iPadのカメラ入力では未検証。

## Ver.0.5 計測・保存の信頼性修正（2026-11-17）
- 数え終わった人物へ、A直前で現れた次の人物が吸収される追跡条件を修正。
- 推論間隔が約1.1秒でも追跡を継続できるよう、直近の処理間隔に応じて追跡の有効時間を調整。1回の解析が1.5秒以上かかる場合は、計測を続けず停止理由を表示する。速い通過の数え漏れはなお実機での検証が必要。
- カメラの終了通知、2.5秒以上の映像更新停止、解析の応答停止を監視。「自動計測中」のまま放置せず停止し、再開を案内する。非表示・スリープ時も停止状態にする。
- 複数タブの補正をIndexedDBの単一トランザクションで処理し、0人から二重に減算される問題を解消。旧版で残った過剰減算も次の加算に対する隠れた負債にしない。同じ端末・同じブラウザでは自動計測を1タブに制限し、人数の変更を他のタブへ通知する。旧版を開いたままのタブは再読み込みが必要。
- 試験IDを人数記録と同じIndexedDBへ保存。localStorageへの書込失敗後の再読み込みでも同じ試験を復元する。DB名・バージョンは維持し、既存の記録を引き継ぐ。
- 保存準備が終わるまで補正・開始ボタンを無効化し、準備中に来た記録も初期読み込みで上書きしない。別タブで新しい試験が始まった場合は古い試験の遅延記録を新試験に混ぜない。
- 解析エラー後は故障したモデルを破棄し、次回開始時に作り直す。停止前の遅延結果も破棄する。
- A・Bの間隔を10%以上に保つ。保存済みの不正な設定で初期化が止まらないようにする。
- `npm run test:people-counter` の64件が通過。追跡・非同期カメラ処理・保存競合・セッション復元・停止監視を検証。ブラウザでも手動補正の再読み込み後の保持と別タブへの反映を確認。iPad実カメラでの認識精度・長時間性能は未検証。


## Ver.0.6 人物判定の追加確認（2026-11-17）
- 胴体の小さな誤ラベルが人物候補を通さないよう、人物枠に対する胴体の高さを20%以上とする。人物枠の最下部にある胴体らしい領域も確認根拠から除外する。
- 胴体を高さ方向の3帯に分け、各帯に領域全体の12%以上の胴体画素があることを確認する。大きな塊に細い橋が付いただけの不自然な形を除外する。頭・脚は引き続き必須にしない。
- 追跡の累計回数に加え、少なくとも2回続けて人物と確認された履歴を必要とする。無人フレームを挟んだ単発の誤検出だけを累積して数えない。一度連続確認できた人の短い遮蔽には対応する。
- モデル・入力画像サイズ・保存内容は変更しない。追加確認は現在のフレームのマスクと短時間の追跡情報を使用し、録画・画像保存・映像送信を追加しない。
- 回帰テスト69件が通過。従来版で受理・加算された4種の合成ケースを修正版で除外できることを確認。既存の実モデル出力18フレームも新しい判定へ再入力し、人物全体・頭なしの肩〜腰を受理、腕と無人を除外できた。画像サンプルは限定的であり、荷物・ポスター・マネキンなどあらゆる対象の誤認識率は未測定。厳格化による見逃しの増加もiPad・会場条件で確認が必要。


## Ver.0.7 胴体＋脚・足先の確認モード（2026-11-17）
- 「人物の確認範囲」で、従来の「肩〜腰」と新しい「胴体＋脚・足先で確認（試験）」を選択できる。初期設定・既存設定は肩〜腰のまま。足先まで見える設置で追加モードを選ぶ。
- 新モードは同じフレームのBodyPix部位IDから、同じ側の太もも（14〜17）・すね（18〜21）・足先（22/23）がつながった領域を確認。少なくとも片側でよく、頭・顔・両脚は要求しない。
- 胴体の下に脚が接続し、太もも→すね→足先の上下関係・大きさ・人物枠との位置関係を満たすことが必要。同じ胴体や脚領域を複数の人物枠に使い回さない。追跡点は胴体の重心のままで、足振りでラインを越えた扱いにしない。
- 足だけ、腕＋足先、足先なし、離れた足、上下逆、左右を混ぜた不完全な脚、近くの他人の脚を受理しない合成テストを追加。設定保存・カメラ処理への反映・切替後の追跡リセットも確認。回帰テスト77件が通過。
- 以前の実モデル出力5場面を再入力し、新モードでは全身の人物を受理、脚の映らない肩〜腰・腕2種・無人を除外。肩〜腰モードでは引き続き頭なしの肩〜腰を受理。1枚の人物画像由来の限定的な検証で、iPadカメラでの服装・靴・横向き・照明条件による精度は未検証。
- 新モードでは足が隠れたり画面外に出たり、モデルが脚を分断すると見逃し得る。足先が映らない設置では肩〜腰モードを使う。追加モデルや録画・画像保存・映像送信は導入しない。

## Ver.0.8 会場設置の検証
- 展示室内の入口横の机にiPadを置き、真横を0°として25°・45°も比較する。角度は検証結果のラベルであり、認識設定を自動変更しない。
- 通行経路を白枠で囲み、Aの手前とBの先を白枠に含める。設定のスライダーか、映像をタップして白枠・ラインを調整できる。判定は白枠内の胴体中心を使う。
- カメラ開始後、角度・設置メモを選んで検証を開始する。同じ通過を目視で数え、検証終了後に実人数を入力する。自動人数・実人数・差と使用設定を端末に保存する。検証中の加算は通常の人数記録に入らない。
- 肩〜腰モードでは、画面上下に接した横長の人物候補に限り、十分な胴体領域がある場合の判定を緩和する。腕だけの候補は引き続き胴体の条件を満たさない。
- カメラなしの自動テストでは、白枠外の通行、引き返し、正常通過、角度別結果、逆方向のタップ操作、部分映りの判定を確認する。
- 実機では、机から入口までの距離、扉の開閉、照明、人数の重なり、足の見切れ、処理速度を確認する。角度以外の条件をそろえ、検証結果の差は過大と過小が相殺され得る点に注意する。

## Ver.0.9 横並び通過の検証
- 人物枠はMediaPipe Object DetectorのEfficientDet-Lite0が最大10件返す。BodyPixは部位ラベルを返し、胴体の連結領域は人物枠と1対1に対応する。肩の重なりなどで2人の胴体がつながると、人物枠が2つあっても従来は1件までしか確認できない場合があった。
- 肩〜腰モードで枠の重なりがあり通常確認で候補が減った場合は、枠ごとに固有の胴体画素で再確認する。ほぼ同一の枠や身体根拠が足りない枠では追加しない。脚・足先モードでは従来の脚の対応条件を使用する。
- 人物ごとの追跡IDを使用する。近い複数候補では予測位置と体の大きさを使い、僅差の組み合わせを調整して追跡を維持する。逆方向は検証表示で区別し、入口の人数には加算しない。
- カメラ画面の検証表示で、AIの返却件数、閾値通過、身体確認、白枠内、追跡と判定理由が分かる。軌跡は直近10点で画面上の表示にのみ使う。推論時間は人物枠と部位推論の合計で、表示するFPSは解析したフレームの頻度。
- 実機ではiPadを入口横の机に置き、背面カメラをやや斜めに向け、横並びでも両者の胴体が映るようにする。1人、横並び2人、近接3人、時間差、短い重なり、停止、引き返し、すれ違いを試し、自動と目視を比較する。AIの返却件数が1なら、追加の人物枠が得られる設置かモデルの検討が必要。実機での認識率と速度は未測定。

## Ver.0.10 通過記録・オフライン運用・滞在時間

1. 入口・出口のiPadを既存の受付端末として同じイベントに承認する。人数カウント画面の「通過記録と滞在時間」で同じイベントIDと実際の開場時刻を設定し、設置先に応じて「入口」か「出口」を選ぶ。通過方向のA→Bを各端末で調整する。
2. 両方のiPadでオンラインのうちに「オフライン用モデルを準備」を実行する。「試験」を選び、通信を切った状態で再読み込みしてカメラが起動することを確認する。初回アクセスとモデル取得には通信が必要。Safariのサイトデータ削除などでキャッシュ・未同期記録を失う場合がある。
3. 試験では、片側だけ切断する場合、両側で切断と復旧を繰り返す場合、未同期のままSafariを閉じて再開する場合を確認する。復旧後に未同期が0になり、両端末の試験集計と目視記録がそろうことを確認する。横並び通過、長時間連続稼働、時刻補正、端末の保存容量も会場のiPadで確認する。
4. 本番の運用モードを選び、通過記録を採取する。カウント漏れは通過時刻を指定して手動登録し、誤検出は対象記録を選択して無効化する。修正と復元には理由を入力する。
5. 閉場後は双方が同期したことを確認し、閉場時刻を入力する。空室と記録の正確さを確認してから確定条件のチェックを入れる。平均は時刻差と人数積分の双方を表示する。開場中は累積人・分と滞在人数を表示し、同期済みかつ異常なしで入場記録が10件以上あり、集計上空室の時点に限って、その時点までの暫定平均を表示する。最終日の平均を予測する機能ではない。
6. 通過記録、修正履歴、時間帯別人数、滞在人数推移、平均滞在時間、整合性結果を個別にCSVで出力できる。時間帯別集計は日本時間、CSVの日時表記はUTC。
