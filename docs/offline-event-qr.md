# オフラインでイベントを受け渡す

初回の端末登録・管理者承認とアプリの保存はオンラインで済ませる。従来のイベント認証QRは認証コードのみなので、引き続きオンラインが必要。

1. 管理画面で対象イベントを公開し、チケット一覧を受信した状態で「オフラインQRを作成・更新」を押す。
2. 「QRをファイルに保存」で単独HTMLを保存する。通信を切る前に、そのファイルを表示側のブラウザーで開けることを確認する。HTMLは外部スクリプト・画像・通信を使わずQRを表示する。印刷して受け渡すことも可能。
3. 承認済みの受付端末で「イベントデータQRを読み取る」（準備済みの場合は「イベントQRを読み直す」）を押し、全ページを読み取る。表示側の「次のQR」でページを切り替える。順番は自由、同じページは重複計上しない。
4. 全ページが揃ったら、管理者が示したQRであること、イベント名、チケット枚数を確認して「このイベントで認証」を押す。「受付準備完了」になれば通信せず受付できる。

QRにはチケット情報自体が含まれる。信頼する管理者から受け取ること。SHA-256は破損・混入を検出するためのもので、管理者の署名を証明するものではない。端末の承認や役割はQRから変更しない。

保存済みの別イベントへの切替は従来の再承認が必要なため、オフラインでは拒否する。同一イベントの更新では古いデータ版への巻き戻しを拒否し、未送信の受付状態を保持する。QRは作成時点のスナップショットであり、その後のチケット追加・無効化・受付状況を自動で反映しない。運用開始前に最新のものを作成する。

gzip、Base64、1000文字単位の分割、内容のハッシュを使用。最大5000枚・解凍後2MB・分割200枚まで。OSのCompressionStream/DecompressionStreamに対応していない場合は明示的に失敗する。500枚の検証データでは5枚のQRになったが、実際の枚数は情報量で変わる。

確認: 500枚の復元、順不同・重複・別データ混入・破損拒否、Firebaseダウンローダーを呼ばない受付準備とオフライン受付、別イベントの再承認保護、単独HTMLのQR生成とイベント名のHTMLエスケープ。iPad実機のカメラでの読み取りと、保存HTMLを開く操作は実機確認が必要。

この機能はイベント初期データの受け渡し用。通信しない別々の入口・出口端末の受付履歴を継続的に同期する機能ではない。
