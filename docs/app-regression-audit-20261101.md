# アプリ全体の回帰確認（2026-11-01）

対象: main a653b91b977da81f60d9d1bbfca573a9af988f0b の管理・受付アプリ。既存の自動テスト群を再実行し、新しいイベント別承認の追加箇所を重点的にコード確認した。全ソースの全分岐を網羅した保証や、全不具合がないという結論ではない。

## 見つかった不具合と修正

1. イベント削除が receptionApprovals を削除対象に含めていなかった。Firestoreでは親削除だけでは子が消えないため、不要データが残り、同じイベントIDを再利用すると以前の承認が復活し得た。イベント本体より先に承認を削除する。削除・同ID再作成後に承認待ちになるテストを追加。
2. 受付画面の初期取得と定期確認が重なったり、複数タブが同時に開くと、承認申請の存在確認と作成が競合する。二つ目の setDoc が更新扱いで拒否されるため、トランザクションで存在確認と作成を一体化。二つの同時申請がエラーなく同じ未承認状態になるテストを追加。一般受付端末が自己承認できないことも検証。

## 自動確認の範囲

| 領域 | 確認内容 |
|---|---|
| 起動・認証 | 永続匿名UIDの復元、未承認時の制限、承認後の購読、取消と再承認 |
| イベント | 作成・保存・公開・切替・終了・再公開・削除、版数と公開チケット数の整合 |
| チケット | 発行の競合、追加発行、削除・変更時の受付状態維持、重複番号、5000枚の保存と取得 |
| 端末 | 同一iPadの管理と受付、イベントごとの再承認、所有者・インストール確認、権限取消 |
| 受付・同期 | 入場・退場・再入場、順序維持、重複再送、不安定通信、未同期履歴の保持 |
| オフライン | IndexedDB、イベントQR転送、承認待ちの迂回拒否、Service Worker、予約券印刷 |
| 管理画面 | イベント切替時の遅延応答、設定保存、バックアップ、分析、印刷・デザイン、練習画面 |
| 権限 | Firestore Emulatorでの匿名・他人UID・不正な役割変更・不正な受付遷移の拒否 |
| 品質 | TypeScript検査、両アプリの本番ビルド、既存の回帰テスト |

## 実施しない本番操作と実機で残る確認

本番データでのイベント削除・受付記録作成・権限変更は実行しない。検証は隔離されたエミュレータで行う。
実際のiPadのカメラ許可・録音音声・Safari/PWA・用紙への印刷は、このテストでは確認できない。
複数端末がオフラインで同じチケットを処理した際の競合や、公開終了後に残った未送信記録は、既存仕様上、履歴を保持して管理者が確認する必要がある。
依存ライブラリの全脆弱性調査・負荷試験・課金状況の実測は今回の回帰テストとは別であり、完了とは扱わない。
